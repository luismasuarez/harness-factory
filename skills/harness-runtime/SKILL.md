# Harness Runtime — Fixed Invariants

You are enforcing the **fixed runtime** of the Harness Factory standard. The
manifest declares the *variable* parts (team, scopes, pipeline). The runtime
below is the *fixed* part — it applies to every harness, every time, and never
changes per project. If a manifest or orchestrator skill contradicts these
invariants, **these invariants win** and the deviation must be flagged.

## The security model (fixed)

| Concern | Invariant |
|---|---|
| Experts | **READ-ONLY** on source. May write only inside the scope artifact root (e.g. `docs/architecture/<scope>/`). |
| Executor | The only write-scoped agent: writes source only inside its declared `writePaths` allowlist. |
| Orchestrator | `mode: primary`. `task` denied for everything except experts + executor. Only orchestrator and executor may edit source, and only after approval. |
| Skill access | Deny-all by default; experts get exactly their own skill. |

## The pipeline contract

Run phases **strictly sequentially — no parallel phases.**

1. **Baseline (HARD GATE).** Before touching anything:
   - `git status` must be clean (or explicitly acknowledged dirty).
   - Run every baseline gate command from the manifest in order.
   - Record the baseline commit SHA.
   - **Tripwire**: if any blocking gate fails, STOP and report. Never start on a
     red baseline. If a gate needs a service (DB, broker) to run, note it and
     ask the user to start it or confirm the baseline is acceptable.
2. **Artifact dir.** Create the scope artifact root (and shared dir for
   cross-scope work) before delegating.
3. **Delegation (READ-ONLY analysis).** Delegate to each expert in manifest
   order via the Task tool, passing the full artifact paths. After each expert
   returns: confirm the artifact was actually written to disk and is
   non-trivial. **If an expert fails or returns nothing useful, STOP and report**
   — never proceed on a missing artifact.
4. **Synthesis (HARD GATE — approval required).** Consolidate all artifacts into
   the plan deliverable as surgical slices:
   - Slice by unit (e.g. one bounded context per slice); never cross units.
   - Behavior-preserving first — refactoring must not change external contracts.
   - Characterization tests when coverage is low/zero BEFORE refactoring.
   - Separate refactor from redesign — no contract change in the same slice as
     a structural move.
   - Each slice must be independently verifiable: refactor → gates → commit.
   Present the plan and **STOP for explicit approval.** No edit before approval.
5. **Execution (only after approval).** Apply slices one at a time:
   - Confirm the slice is within the approved plan.
   - Apply the slice exactly (the blueprint is the source of truth).
   - Run the per-slice gates. Lint semantics: `expect: no-new-errors` passes on
     no NEW errors over baseline; auto-fixes revert only known alien files, never
     slice files.
   - Green → commit the slice (stage only slice paths + blueprint; never
     `git add -A`, never amend, never push). Red → **REVERT the slice
     immediately** per its rollback and report. Never proceed on a red tree.

## Tripwire semantics

A gate with `blocking: true` that fails is a **tripwire**: a hard, immediate
STOP. Do not paper over it, do not "fix forward", do not skip. Revert to the
last green state, report the failure verbatim, and ask how to proceed.

## Artifact discipline

- Artifacts are historical records; never overwrite a run's artifacts with a
  run targeting a different scope.
- Every Task delegation passes the full artifact paths + scope name.
- An expert that cannot load its skill (tool unavailable in subagent context)
  is not silently skipped: load the skill yourself and inject its methodology
  into the delegation prompt.

## Memory protocol

- Save harness runs, gate results, slice boundaries, and deviations to memory so
  future sessions resume from the last green state.
- After a completed run, record what changed (files, commit SHAs, gate numbers)
  for the acceptance diff.

## Non-negotiable

- No code edits before approval.
- Never skip a gate. Never parallelize phases.
- Permission denials are reported verbatim, never worked around.
- The runtime is fixed; only the roster/pipeline/scopes vary (in the manifest).
